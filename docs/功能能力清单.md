# 灵动 Code / 灵动 Agent — 功能与能力清单

> 版本锚点：产品 `0.1.0`，扩展 `lingdong-agent@0.1.0`  
> 基座：microsoft/vscode（Code-OSS）源码构建（见 `docs/code-oss-build.md` / `desktop/`）  
> 运行时：Grok Build（默认经 `scripts/fetch-grok.ps1` 获取官方预编译；自建见 `docs/grok-源码构建.md`）  
> 文档性质：**现货能力**（以仓库源码与打包脚本为准），不是路线图。  
> 编译与 DIY：优先 `docs/给大模型的构建与 DIY 指南.md`。

---

## 1. 产品是什么

**灵动 Code** 是一个 Windows 桌面应用：在干净机器上装完即可用，不要求用户预先安装 VS Code、Node 或 Grok。

它由三块拼成：

| 层 | 是什么 | 作用 |
|---|---|---|
| **桌面壳** | VSCodium 二进制再封装为 `Lingdong.exe` | 提供编辑器宿主、窗口、信任工作区等 |
| **灵动 Agent** | 预装的 VS Code 扩展 | 对话面板、会话、计划、变更、权限、模型中心 |
| **Grok Build** | 捆绑的 `grok.exe` | 真正执行 Agent 工具调用的子进程（经 ACP 协议连接） |

安装包路径（构建产物）：

- 安装程序：`.build/out/LingdongCodeSetup-0.1.0.exe`
- 安装目录：`%LOCALAPPDATA%\Programs\Lingdong Code`
- 用户级安装，不弹 UAC；不写 PATH，不注册文件关联/右键菜单
- 当前安装包**未做代码签名**（SmartScreen 可能拦截）
- **没有自动更新通道**（`updateUrl` 已清空）

快捷键总览（部分）：

| 快捷键 | 作用 |
|---|---|
| `Ctrl+Alt+L` | 打开 Agent 主面板 |
| `Ctrl+Alt+N` | 新建会话 |
| `Ctrl+Alt+M` | 切换模式 |
| `Ctrl+Alt+H` | 会话历史 |
| `Ctrl+Alt+K` | 添加选中代码到上下文 |
| `Ctrl+Alt+U` | 添加当前文件到上下文 |
| `Ctrl+Alt+Backspace` | 停止当前任务（忙时） |

## 2. 界面形态

### 2.1 Agent 形态（默认）与 IDE 形态

| 形态 | 表现 |
|---|---|
| **Agent**（默认） | 收起活动栏与主侧边栏，对话面板占满编辑区；文件树在面板内部的「仓库树」里 |
| **IDE** | 显示活动栏与 VS Code 资源管理器，Agent 面板作为其中一个标签 |

- 每个文件夹**第一次打开**时按设置摆一次布局，之后你手动怎么调就怎么留着
- 命令：`灵动 Agent: 切换 Agent / IDE 形态`
- 设置项：`lingdongAgent.windowShape` = `agent` | `ide`

### 2.2 主面板布局

中间是对话列（时间线 + Composer），左侧是「仓库 → 会话」树，右侧是可开关的工作台轨道（Changes / Files / Tasks / Context / Plan / Browser / Terminal）。

辅助侧栏另有独立 Webview：Plan、Tasks、Changes、Context（与主面板共享数据源）。

### 2.3 首次运行引导

按状态分三档欢迎页：

1. **没有仓库** → 引导添加文件夹  
2. **没有 API Key** → 引导打开模型设置（密钥进系统凭据库）  
3. **就绪但无会话** → 引导新建 Agent / 打开主面板 / 搜索会话  

缺 Key 时还会弹一次信息提示，避免用户对着空白界面不知道缺什么。

## 3. 活动仓库（与 VS Code 工作区解耦）

这是近期落地的核心能力：**Agent 操作的「仓库」不再等于 VS Code 的 `workspaceFolders`**。

### 已实现行为

- 活动仓库记在扩展 `globalState`（键 `lingdongAgent.activeRepo`）
- 添加 / 切换仓库 = 内部拆建（停任务 → 落盘 → 重建会话存储与变更跟踪 → 重启 Grok）
- **窗口不重开、不重载**
- 无记录时回落到宿主打开的第一个文件夹（「直接打开文件夹就用」仍成立）
- 文件列表、`@` 候选、Plan 概览走自有广度优先目录扫描（因为目标目录可能不在宿主工作区里）
- 会话按仓库路径哈希分目录存；切走再切回，原来的会话还在
- 编辑器里还开着、但不是当前仓库的文件夹，会列在当前节点下，点一下也能切过去

### 刻意不做

- 跨仓库的全局会话索引 / 搜索（需要扫所有存储目录，复杂度不值得）

## 4. 五种工作模式

UI 模式：`ask` / `plan` / `agent` / `auto` / `debug`  
默认 **Agent**。未通过「工具调用」能力检测的模型会被强制为 **Ask**。

| 模式 | 能做什么 | 不能 / 特别之处 |
|---|---|---|
| **Ask** | 只读问答、读文件、解释代码 | 写/删硬拒；执行命令需确认；检测到「想改代码」的意图时提示切模式，**不静默切换** |
| **Plan** | 调研仓库、产出结构化计划、澄清问答 | Runtime 侧只允许读；宿主注入只读研究引导 |
| **Agent** | 改文件、跑命令、完整工具链 | 审批力度由 `approvalPolicy` 控制；改前有快照 |
| **Auto** | 低风险自动放行；工作区内写操作中等风险放行 | 高风险硬拒；其余中等风险仍询问 |
| **Debug** | 收集诊断 → 等你确认 → 再切 Agent 发修复提示 | **本地编排**，不是 Grok 原生 debug 模式；Runtime 侧映射为 Ask |

任务执行中切换模式会挂到本轮结束；Runtime 回写失败会回退。

Composer 里可用模式芯片切换，也可用 Slash：`/ask` `/plan` `/agent` `/auto` `/debug`。

## 5. 对话与 Composer

### 5.1 核心交互

- 流式渲染助手回复 + thinking 指示器（时长跨阶段累计）
- 活动时间线：按 turn / group / item 增量推送（工具调用、读写、命令等）
- 发送队列：忙时入队，上限 **10**；可删除单条；空闲时自动续发；停止/失败**不**自动续发
- 停止当前任务（按钮 / 命令 / 快捷键）
- 面板打开即后台预热 Grok 连接（失败不锁界面）
- 断线后自动重连（退避约 1s → 3s → 8s），也可手动「重新连接 Grok」
- 会话内搜索：在已渲染记录上查找，并按需补页
- 单条提示上限：**20_000** 字符

### 5.2 Slash 命令

切模式（可带需求，切完顺手发出去）：`/ask` `/plan` `/agent` `/auto` `/debug`  
会话与任务：`/new`（别名 `/clear`）`/stop` `/retry` `/history`（`/resume` `/sessions`）  
上下文：`/compact` `/context`（`/usage` `/cost`）`/clear-context`  
打开面板：`/changes` `/files` `/terminal` `/browser` `/rules`（`/skills` `/mcp` `/memory` `/hooks`）
`/model`（`/m` `/models`）`/settings`（`/config` `/preferences`）  
诊断：`/logs`（`/doctor`）`/reconnect` `/help`

未接入的命令在 `NATIVE_ONLY_COMMANDS` 里逐条明确拒绝并给替代做法，绝不当普通消息发给模型。
这张表混着两类：`/theme` `/vim` `/fullscreen` 这些说的是终端界面自己的渲染方式，搬过来没意义；
而 `/goal` `/workflow` `/deep-research` 是 **Agent 侧支持、我们还没接**——
`scripts/probe-slash-over-acp.mjs` 实测 `agent stdio` 会 advertise 命令清单，
且斜杠命令经 `session/prompt` 就能由 Agent 侧解析执行，拦住它们的是缺 UI 与编排，不是协议。

### 5.3 Composer 附件与菜单

- `@` 内联建议（候选 ID 不透出绝对路径）
- ＋菜单：加文件 / 选区 / 文件夹 / 终端输出 / 问题面板等
- 模型选择、用量显示、上下文 chips
- Skills：扩展面板里管理，Composer 可引用；变更后重写 Grok 配置
- 用户可配 MCP：扩展面板里增删 / 启停 / 填凭据，变更在新一轮对话生效
- 图片：拖入、粘贴、＋菜单选择皆可，字节交宿主暂存后变成上下文 chip；
  当前模型不支持看图时明确拒绝，不静默丢弃
- 文件拖放：应用内拖拽（编辑器标签/资源管理器）走 uri-list 按路径添加；
  系统资源管理器拖入的文件拿不到路径（Electron 安全模型），按文件名在仓库内还原、
  同名多个按内容比对，还原不了明确拒绝。
  依赖桌面壳的拖放策略反转（`webviewWindowDragMonitor.ts` 源码补丁：默认交给
  webview，Shift 才让编辑器打开；已打包产物用 `desktop/scripts/patch-webview-drag.mjs` 就地翻转）

## 7. 上下文系统（@ 引用）

### 类型

`file` · `selection` · `folder` · `terminal` · `diagnostics`

### 入口

- Composer 内 `@` 建议
- Composer ＋菜单
- 命令 / 快捷键（当前文件、选区、多文件、文件夹、终端选中、问题面板）
- Slash：`/clear-context` 等

### 限额与边界

| 项 | 上限 |
|---|---|
| 选区 | 约 30k 字符 |
| 单文件 | 约 200KB |
| 文件夹 | 约 50 文件 / 300k 字符 |
| 终端缓冲 | 约 20k 字符 |
| 总条目 | 20 |

- 严格限制在**当前活动仓库**内；越界拒绝
- 排除 `node_modules`、`.git`、构建产物、二进制、凭据类路径等
- 注入前做密钥脱敏
- 用量：exact / estimated / unavailable；可手动压缩上下文（若 Runtime 支持 `compactConversation`）

## 8. Plan（计划）能力

### 生命周期

调研 → 生成结构化计划 →（澄清问答）→ 批准 / 放弃 / 反馈修订 → 开始构建 → 可暂停 / 继续 → 步骤同步为执行期 todo

### 计划内容结构（节选）

目标、步骤、涉及文件、风险、澄清问题、状态全生命周期。

### UI

- 主面板计划文档视图（渲染态直接改，不是源码框）
- 右轨 / 辅助侧栏 Plan 面板
- 执行期 todo 卡片（与审批步骤同步）
- 步骤勾选：取消勾选记成「已跳过」，条目仍看得见，随时勾回来
- 步骤编排区（默认折叠，与正文共存）：拖拽排序、上移下移、增删、改标题与文件
- 可导出为工作区 Markdown（「保存计划到工作区」）

### 审批

- 批准 → 切到 Agent 模式并**直接开跑**，不需要再点一次「开始构建」
- 放弃
- 带反馈修订（反馈上限约 4k 字符）

### 逐步门控（`lingdongAgent.planStepGating`，默认开）

开着时宿主一轮只下发一步，拿到轮次结果后再推进下一步：
成功记 completed 继续，失败或被停就停在那一步并给出提示，不会闷头往下跑。
关掉则退回整份计划一次性发给模型。

Plan 模式下宿主可提供仓库文件概览（扫描约 120、展示约 80），避免模型默认狂刷 `dir`/`ls`。

## 9. 变更、快照与 Diff

### 跟踪

按轮次记录 create / modify / delete / rename；状态：pending / accepted / rejected / conflict / restored。

### 操作

- 单文件接受 / 拒绝
- 整轮全部接受 / 全部拒绝
- 打开 Diff 查看本轮变更
- **撤销本轮修改**（先停任务、清权限队列，再按哈希校验恢复）
- 冲突展示

### 边改边看（`lingdongAgent.streamEditPreview`）

模型改文件时编辑器里同步给出预览，三档：

- `off`（默认）：什么都不开
- `diff`：开一个改前 / 改后的 diff 编辑器
- `reveal`：只把被改的文件亮出来，不开 diff

默认关掉是实测的结论：一轮能改九个文件，自动开标签会把用户正在看的文件反复顶掉，
观感是「它乱开我的文件」。超出体量上限或工作区外的文件一律不预览。

行数不依赖这个开关：变更摘要卡每行路径后跟 `+N/-N`、卡头给出本轮合计，
时间线条目与结算行同样带行数。

### 快照策略

- 改文件前落盘快照（目录：`agent-snapshots/<仓库哈希>/`）
- 配置：
  - `lingdongAgent.snapshotRetentionDays`（默认 30 天）
  - `lingdongAgent.snapshotMaxTotalMb`（默认 512 MB）
- **未处理**与**冲突**快照不会被自动删除
- 超配额时优先清理最旧的已接受 / 已恢复快照

## 10. 权限、风险与提问

### 风险分级（Runtime 本地计算）

`low` / `medium` / `high` / `blocked`

`blocked` 永不放行（提权、注册表、磁盘格式化、系统级安装、强制推送等）。

### Agent 审批力度（`lingdongAgent.approvalPolicy`）

| 策略 | 含义 |
|---|---|
| **balanced**「均衡」（默认） | 工作区内文件改动、构建/测试、git 提交自动放行；删除、push、装依赖、访问网络仍确认 |
| **strict**「严格」 | 只自动放行只读；其余逐项确认 |
| **yolo**「放行」 | 除硬性禁止项外全部放行 |

任何力度都不会放行：越界访问、凭据读取、硬性禁止命令。每笔文件改动仍有改前快照，可从变更面板撤销。

### 权限卡片决策

`allow_once` · `allow_session` · `allow_always` · `reject`

- 等待超时默认 300 秒（可配，最小 10 秒），超时自动拒绝
- 「以后都允许」按仓库持久化；命令可一键清空已记住规则
- 队列有上限；连续拒绝会提示

### 模型提问（ask_user_question）

模型可向用户提问（多选 / 自由文本）；**无超时**，等用户回答。

## 11. 模型与服务商

### 已支持的服务商类型

| 类型 | 说明 |
|---|---|
| **DeepSeek** | 首次播种；默认模型 `deepseek-v4-flash`（约 1M 上下文，预标 agent 兼容） |
| **Poe** | 用户可一键添加；支持目录同步、余额查询 |
| **自定义 OpenAI 兼容** | 用户自填 base URL / 协议 |

协议面：`responses` / `chat_completions` / `messages` / `openai_compatible`。

### 模型设置中心

- Provider 列表与编辑
- API Key 写入 **VS Code SecretStorage**（配置 JSON 只存 `secretId`，不落明文）
- 模型列表、连接测试
- **能力探测**（能否进入 Agent 模式）
- Poe 目录同步
- 自定义 Provider、删模型规则、切换守卫
- Provider 找不到或缺 Key：**不会自动回退到别的 Provider**

### 相关设置

- `lingdongAgent.model`：当前模型标识（默认 `deepseek-v4-flash`）
- `lingdongAgent.sanitizeUpstreamResponses`：本地回环转发，修补部分服务商 usage 里的 `null`（如 Poe 上某些模型否则整轮解析失败）

## 12. Runtime、Grok 与隐私

### 连接方式

扩展通过 `@lingdong/agent-runtime` 拉起 `grok agent stdio`，走 ACP（JSON-RPC）协议通信。

### Grok 可执行文件定位顺序

1. 设置 `lingdongAgent.grokExecutable`  
2. 环境变量 `LINGDONG_GROK_EXECUTABLE`  
3. **安装包捆绑路径** `resources/grok/bin/grok.exe`  
4. PATH  
5. 常见安装位置  

也可命令「选择 Grok 可执行文件」手动指定。

### 托管 GROK_HOME（默认开启）

- 扩展在自己的存储下维护 `grok-home/`
- 由扩展生成 `config.toml`
- 强制关闭：遥测、反馈、远程目录抓取、Mixpanel、Trace 上传、OTel、自动更新等
- 原用户 GROK_HOME **只读播种**，不直接改写
- 设置 `lingdongAgent.managedGrokHome` / `lingdongAgent.grokHome` 可覆盖行为

### 宿主联网能力（内置 MCP）

捆绑脚本提供：

- **WebSearch**：DuckDuckGo / Bing 检索  
- **WebFetch**：抓取页面（禁止内网 / loopback）  

写入 Grok 的 MCP 配置，供 Agent 调用。这两个是宿主自带、不可删的；
用户自己的 MCP 服务器在扩展面板里管理（增删、启停、凭据），与它们并存。

### 隐私与脱敏

- 子进程环境剥离凭据 deny-list
- 日志、转写、错误信息过 redact
- 命令：「查看隐私状态」

工作区信任：扩展声明 **不支持未信任工作区**（否则会在受限模式下无声消失，用户只觉得产品坏了）。

## 17. 建议的验收路径（装完怎么点）

1. 安装 `LingdongCodeSetup-0.1.0.exe`，启动后打开或添加一个文件夹  
2. 确认默认是 **Agent 形态**（没有左侧 VS Code 资源管理器那一列）  
3. 模型设置里确认已有可用 Key（DeepSeek / Poe / 自定义任选）  
4. Ask 模式问一句只读问题；Agent 模式让它改一个小文件，看变更面板与 Diff  
5. 点 `＋` 再加一个仓库：**窗口不应重开**；切回去，原会话应还在  
6. Plan 模式要一份小计划 → 批准 → 开始构建  
7. 故意触发一次需确认的命令，走完权限卡片（允许一次 / 本会话 / 以后都允许）  
8. `Ctrl+Shift+P` →「切换 Agent / IDE 形态」来回切一次  

出问题看：输出面板选「灵动 Agent」通道；布局相关有 `[shape]`，切仓库有 `[workspace]`。
