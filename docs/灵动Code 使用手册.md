# 第一部分 · 功能清单

## 1. 灵动 Code 是什么

灵动 Code 是一个**装完就能用的 Windows 桌面 AI 编程工作台**。你打开一个代码文件夹，用中文说要做什么，它自己去读文件、改代码、跑命令、验证结果，每一步都摆在你眼前，改错了能一键退回去。

它不要求你预先装 VS Code、Node 或任何命令行工具——三层能力打包在一个安装程序里：

| 层 | 是什么 | 你感知到的部分 |
|---|---|---|
| 桌面壳 | 基于 microsoft/vscode（Code-OSS）源码构建的 `Lingdong.exe` | 编辑器、窗口、文件树、终端 |
| 灵动 Agent | 预装扩展 | 对话面板、计划、变更审阅、权限卡片、模型设置 |
| Grok Build | 捆绑的 `grok.exe` 子进程 | 真正干活的那个引擎（你不用管它在哪） |

**和「网页版聊天再复制粘贴」的区别**：它直接在你的仓库里动手，改动有快照可回退，命令要不要执行由你拍板。

**和普通补全插件的区别**：它做的是整件任务——「把这三个页面的导航补齐并互相链上」这种活，它会自己拆步骤、逐个改、改完还回头检查。

## 2. 它替你做的十件事

### ① 读懂一个陌生仓库

用 **Ask 模式**问「这个项目的入口在哪、构建流程是什么」。它会真的去读文件、搜索代码，读过哪些文件都列在时间线上，不是凭空编。Ask 模式下**写和删是硬拒绝**的，你可以放心让它到处翻。

> 作用：接手别人的代码、看不懂的老项目、上手第一天。

### ② 直接改代码，并且改错能退

**Agent 模式**下它可以建文件、改文件、删文件。每一笔改动落盘**之前**都会先存一份快照，所以：

- 对话流里会出现一张「本轮修改了 N 个文件」的卡片，每行带 `+N/-N` 行数
- 每个文件可单独**接受 / 拒绝**，也可以整轮全接受、全拒绝
- 点「Diff」看改前改后对比
- 整轮不满意就「撤销本轮修改」，按哈希校验安全回退

> 作用：让它动手，但主动权在你手上。

### ③ 先出计划再动手

**Plan 模式**下它只读不写，先调研仓库，然后产出一份结构化计划：目标、分步骤、每步涉及哪些文件、风险点、需要你澄清的问题。你可以：

- 勾掉不想做的步骤（记成「已跳过」，随时勾回来）
- 拖拽调整步骤顺序、增删步骤、改标题
- 批准（**批准即开跑**，不用再点一次「开始构建」）、放弃，或者带一段反馈让它改计划
- 执行中随时暂停 / 继续

默认开启**逐步门控**：一轮只下发一步，这一步成功了才推进下一步；失败或被停就停在那一步并告诉你，不会闷头往下跑。

> 作用：改动面大的活儿，先对齐再动手，比事后返工便宜。

### ④ 跑命令、构建、测试

它可以执行终端命令。风险由本地策略分级，高风险和越界操作会弹权限卡片让你拍板；提权、格式化磁盘、改注册表、强制推送这类**硬性禁止项永不放行**，任何设置都放不开。

长时间运行的命令会变成一张**后台任务卡片**，输出实时接到卡片上，可以终止。

> 作用：装依赖、跑测试、构建打包这些活它能自己收尾，不用你在两个窗口之间来回切。

### ⑤ 改完自己复查

默认开启**编辑后校验**：它改完文件会自动跑一遍检查（类型检查 / lint 这类），有问题自己接着修，而不是把一堆报错留给你。

> 作用：少一轮「你改的东西编译不过」。

### ⑥ 联网查资料

内置两个宿主提供的联网能力（不可删、不可篡改）：

- **WebSearch**：DuckDuckGo / Bing 检索
- **WebFetch**：抓取指定网页正文（禁止访问内网与本机回环地址）

> 作用：查 API 文档、看报错原因、抄一个官方示例。

### ⑦ 派分身并行干活

任务可以拆给多个**子 Agent** 并行做，右侧 Tasks 面板一张卡一个分身，能看到它在跑什么、跑多久、交回了什么结论（展开「查看汇总」）。

> 作用：一次调研三个方向，不用排队等。

### ⑧ 教它你的规矩

| 能力 | 作用 |
|---|---|
| **项目规则** | 把「这个项目必须用 pnpm」「注释写中文」这类约定写进规则文件，每轮自动带给它 |
| **跨会话记忆**（默认关） | 让它把项目约定与结论长期记在本机，新会话自动带回 |
| **Skills** | 把一套复杂流程封装成技能，对话里用 `/技能名` 触发 |
| **MCP 服务器** | 接入外部工具（数据库、内部 API、第三方服务） |
| **语言服务（LSP）** | 开启后它能用「跳转定义 / 找引用 / 看类型」这类代码智能，而不是纯文本搜索 |

规则文件兼容 Cursor 与 Claude 的目录约定，从别的工具迁过来可以直接复用。

> 作用：越用越顺手，同一句话不用交代第二遍。

### ⑨ 换模型不换工作流

内置 DeepSeek，一键添加 Poe，也支持任何 OpenAI 兼容接口的自定义服务商。密钥存进 **Windows 系统凭据库**，配置文件里只有一个引用 ID，界面上永远不回显密钥。

添加模型时自动测连接，并做**能力探测**——探测不通过（不支持工具调用）的模型会被限制在 Ask 模式，避免你选了个改不了代码的模型却不知道为什么它一直不动手。

> 作用：哪家便宜好用就用哪家，工作流不变。

### ⑩ 安全兜底

- **改前快照**：每笔文件改动都有回退点
- **审批力度三档**：从「只放行只读」到「除硬禁止项全放行」，自己定
- **越界拒绝**：上下文与文件操作严格限制在当前仓库内
- **脱敏**：日志、会话记录、错误信息里的密钥会被抹掉；子进程环境剥离凭据
- **托管配置**：引擎的遥测、远程抓取、自动更新等一律强制关闭

## 3. 功能总表

| 模块 | 能力 | 主要入口 |
|---|---|---|
| 对话 | 五种模式、流式回复、可展开推理链、停止、重试、发送队列（上限 10）、断线自动重连 | 主面板 Composer |
| 上下文 | `@` 引用文件 / 选区 / 文件夹 / 终端输出 / 问题面板；图片拖入或粘贴 | Composer 的 `@` 与 `＋` |
| 会话 | 新建、搜索、固定、归档、重命名、删除；按仓库分开保存 | 左栏会话树 / `Ctrl+Alt+H` |
| 仓库 | 多仓库切换，**切换不重开窗口**，切回来会话还在 | 主面板仓库树的 `＋` |
| Plan | 结构化计划、澄清问答、步骤勾选与拖拽编排、批准即开跑、逐步门控、导出 Markdown | Plan 模式 / 右侧 Plan 面板 |
| 变更 | 逐文件接受拒绝、整轮接受拒绝、Diff、撤销本轮、`+N/-N` 行数、冲突提示 | 对话流变更卡 / 右侧 Changes |
| 任务 | 子 Agent 并行卡片、后台任务卡片（实时输出、可终止） | 右侧 Tasks |
| 安全 | 风险分级、审批力度三档、权限卡片四种决策、持久规则可清空 | 权限卡片 / 设置 |
| 引擎能力 | 项目规则、跨会话记忆、Skills、用户 MCP、语言服务 | 「Agent 能力」页 / `/rules` |
| 联网 | WebSearch、WebFetch（宿主内置，不可删） | 模型自行调用 |
| 模型 | DeepSeek / Poe / 自定义 OpenAI 兼容；密钥入系统凭据库；连接测试、能力探测、余额查询 | 「模型设置」页 / `/model` |
| 工作台 | Changes / Files / Tasks / Context / Plan / Browser / Terminal | 主面板右轨 |
| 界面 | Agent 形态（沉浸对话）与 IDE 形态（标准编辑器）互切 | `Ctrl+Shift+P` → 切换形态 |
| 诊断 | 运行日志、隐私状态、Agent 诊断（规则与能力） | `/logs`、命令面板 |

**当前不提供**：账号体系、跨仓库全局会话搜索、Preview 工作台、安装包代码签名、自动更新、未信任工作区支持。

# 第二部分 · 操作说明书

## 4. 第一次启动：三步跑通

### 第 1 步：打开一个代码文件夹

启动后如果是空界面，按引导「添加文件夹」，或菜单 **文件 → 打开文件夹**。

> 灵动 Code 需要**信任的工作区**。弹出信任询问时选「是，我信任此作者」，否则扩展会在受限模式下不工作。

### 第 2 步：配置一个模型密钥

没有密钥它什么都干不了，界面会主动提示。进入方式任选：

- 对话框里输入 `/model` 回车
- 左下角 **设置** → 模型设置
- 命令面板（`Ctrl+Shift+P`）→ **打开模型设置**

在模型设置页里：

1. 在服务商列表里选一个（内置 DeepSeek；也可一键添加 Poe；或点「添加自定义服务商」填自己的 Base URL）
2. 展开它，填入 API Key，保存 → 密钥进入 Windows 凭据库，页面不再显示
3. 在下方填 Model ID 点添加，**添加时会自动测试连接**
4. 关注「能力探测」结果：通过才能用 Agent 模式改代码；不通过只能 Ask

### 第 3 步：发第一条消息

回到主面板（`Ctrl+Alt+L`），确认左下角模式芯片是 **Agent**，输入框里写一句人话，回车。

**建议第一句这样试**：先用 Ask 问「这个项目是做什么的，入口文件在哪」，确认它能读到你的代码；再切 Agent 让它改一个小文件，走一遍变更审阅流程。

## 5. 界面认路

默认是 **Agent 形态**：没有 VS Code 左侧那一列活动栏图标，对话占满整个编辑区。

```
┌──────────────┬────────────────────────────────┬──────────────┐
│  左栏         │  中间：对话列                    │  右轨         │
│              │                                │              │
│ 新建对话      │  助手回复（流式）                │  Plan        │
│ 搜索会话      │  思考块（可展开看推理原文）        │  Tasks       │
│ ─────        │  时间线（读了什么、改了什么）       │  Changes     │
│ 仓库树 ＋     │  变更摘要卡（+N/-N、接受/拒绝）    │  Context     │
│  └ 会话列表   │  权限卡片（需要你拍板时）          │  Files       │
│              │  ──────────────────────       │  Browser     │
│ 设置   日志   │  Composer：模式 / 模型 / ＋ / @   │  Terminal    │
└──────────────┴────────────────────────────────┴──────────────┘
```

要标准 IDE 布局（左侧资源管理器 + 对话作为一个标签）：`Ctrl+Shift+P` → **切换 Agent / IDE 形态**。每个文件夹第一次打开时按设置摆一次，之后你手动怎么调就怎么留着。

**几个容易找不到的地方**：

| 你想找 | 在哪 |
|---|---|
| 模型下拉、模式芯片 | 输入框下面一行 |
| 加文件 / 加选区 / 加终端输出 | 输入框左下角 `＋` |
| 上下文占了多少 | 输入框右侧的用量，或 `/context` |
| 它现在在干什么 | 中间对话流的时间线 + 底部状态行 |
| 子 Agent 和后台任务 | 右轨 **Tasks** |
| 本轮改了哪些文件 | 对话流的变更卡，或右轨 **Changes** |
| 运行日志 | 左下角 **日志**，或 `/logs` |

## 6. 一轮完整对话怎么走

### 6.1 选模式

输入框下方的模式芯片，或 `Ctrl+Alt+M`，或直接打斜杠命令：

| 模式 | 什么时候用 | 边界 |
|---|---|---|
| **Ask** | 只想问、不想它动手 | 写/删硬拒；跑命令要确认 |
| **Plan** | 改动面大，想先看方案 | 只读；产出结构化计划 |
| **Agent**（默认） | 让它动手干 | 按审批力度确认；改前有快照 |
| **Auto** | 信任度高、想少点几下 | 低风险自动放行，高风险仍硬拒 |
| **Debug** | 排查一个具体故障 | 先收集诊断 → 你确认 → 再切 Agent 修 |

任务执行中切模式会挂到本轮结束再生效。

> 小技巧：斜杠命令可以带上要做的事，一步到位——`/plan 把登录页拆成组件` 等于「切到 Plan 模式」+「发这句需求」。

### 6.2 给它看该看的东西

它自己会搜文件，但你直接指出来更快更省 token：

- 输入框里打 `@` 然后输入文件名，从候选里选
- 或用 `＋` 菜单：加当前文件、加选区、加文件夹、加终端输出、加问题面板
- 编辑器里选中一段代码按 `Ctrl+Alt+K`；想加整个当前文件按 `Ctrl+Alt+U`
- 图片：直接拖进对话面板，或 `Ctrl+V` 粘贴（当前模型不支持看图时会明确拒绝，不会静默丢掉）
- 文件：从编辑器标签或资源管理器直接拖进对话面板，变成文件上下文。
  从系统文件管理器拖入时按文件名在仓库里定位（同名多个按内容比对），
  不在仓库里的会明确拒绝——上下文只能来自当前仓库。
  **按住 Shift 拖**则交给编辑器打开文件，不进对话

**限额**（超出会截断并告诉你）：

| 类型 | 上限 |
|---|---|
| 选区 | 约 30,000 字符 |
| 单文件 | 约 200 KB |
| 文件夹 | 50 个文件 / 300,000 字符 |
| 终端输出 | 约 20,000 字符 |
| 上下文条目总数 | 20 条 |
| 单条消息 | 20,000 字符 |

上下文只能来自**当前活动仓库**，越界会被拒绝；`node_modules`、`.git`、构建产物、二进制、凭据类路径自动排除；注入前做密钥脱敏。

觉得上下文太满：`/compact` 压缩，或 `/clear-context` 清掉待发送的上下文。

### 6.3 看它干活

- **思考块**：折叠的「思考 Ns」，展开能看推理原文（原文只在内存里，不落盘，重开面板即消失；不想看可在设置里关掉 `showReasoning`）
- **时间线**：读了哪些文件、搜了什么、改了什么、跑了什么命令，带耗时和行数
- **底部状态行**：当前在做什么、等谁（等你批权限 / 等子 Agent）
- 忙的时候还能继续发消息，会**排队**（上限 10 条），空闲后自动续发；被停止或失败**不会**自动续发

要停：点停止按钮、按 `Ctrl+Alt+Backspace`，或 `/stop`。

### 6.4 收尾

一轮结束会出现变更摘要卡（如果它改了文件）。接下来走第 8 节的审阅流程。

「已接受 N 个文件的修改」这类回执卡片**几秒后自动消失**，不用手动关；警告和错误会留在对话流里等你处理。

## 7. 让它先出计划再动手

**完整流程**：

1. 切 **Plan** 模式，说清目标：`/plan 给后台加一个用量统计页`
2. 它调研仓库（只读），然后给出计划文档：目标 / 步骤 / 涉及文件 / 风险 / 待澄清问题
3. 有澄清问题就在卡片上回答
4. 审阅计划：
   - **不想做的步骤**：取消勾选 → 记为「已跳过」，条目还在，随时勾回来
   - **顺序不对 / 想加一步**：展开「步骤编排」（默认折叠）→ 拖拽排序、上移下移、删除、添加、改标题与涉及文件
   - **整体方向不对**：点「放弃」，或用「反馈修订」写一段意见（约 4,000 字符内）让它重做
5. 点 **批准** → 自动切到 Agent 模式并**立即开始执行**，不需要再点「开始构建」
6. 执行中：右侧 Plan 面板显示每步状态（进行中 / 已完成 / 已跳过 / 失败），可**暂停** / **继续**
7. 想把计划留档：命令面板 → **保存计划到工作区**，导出成 Markdown

**逐步门控**（`lingdongAgent.planStepGating`，默认开）：宿主一轮只下发一步，拿到结果再推进；某一步失败或被停就停在那里并提示你，不会带着错误继续往下做。想让模型一次拿到整份计划自己跑，把这个设置关掉。

## 8. 审阅与回退它的改动

### 8.1 变更摘要卡

一轮改完，对话流里出现「本轮修改了 N 个文件」：

- 卡头：`修改 5 · 新增 4 · +312 -47`（本轮行数合计）
- 每行：文件状态字母（A 新增 / M 修改 / D 删除 / R 重命名）、路径、`+N/-N`、操作按钮
- **展开**：就地看这个文件的 diff，不用切编辑器
- **Diff**：在编辑器里开标准对比视图
- **接受 / 拒绝**：逐个文件处理
- 卡片底部可整轮**全部接受** / **全部拒绝**

### 8.2 撤销整轮

命令面板 → **撤销本轮修改**。它会先停任务、清掉待处理的权限请求，再按哈希校验逐个恢复。文件在它改完之后又被别人（或你）动过，会标成**冲突**并跳过，不会覆盖你的手改。

### 8.3 要不要让它自动打开文件

默认**不自动打开**任何编辑器标签（`lingdongAgent.streamEditPreview` = `off`）。这是实测后的默认值：一轮能改十来个文件，自动开标签会把你正在看的东西反复顶掉。

想要边改边看，把这个设置改成：

- `diff`：一改就开一个「改前 / 改后」对比标签，落盘后右侧变成真实文件，可就地继续编辑
- `reveal`：只把它正在改的文件亮出来，不开对比视图

两档都用临时标签且不抢输入焦点，标签会互相顶掉而不是无限堆积。**行数 `+N/-N` 不依赖这个开关**，始终显示在变更卡上。

## 9. 权限卡片怎么选

它要做有风险的事时，会停下来弹一张卡片，写明操作、目标、风险等级和原因。四个按钮：

| 按钮 | 含义 | 什么时候用 |
|---|---|---|
| **允许一次** | 只放行这一次 | 默认选它 |
| **本次会话允许** | 这个会话内同类操作不再问（高风险不可用） | 同一类操作要重复很多次 |
| **以后都允许** | 按仓库持久记住（风险过高或存储不可用时不出现） | 你完全信任的常规操作 |
| **拒绝** | 不放行 | 看着不对就拒绝，它会换路子或问你 |

**等待超时默认 300 秒**，超时自动拒绝（可在设置里调，最小 10 秒）。
清空记住的规则：命令面板 → **清空已记住的权限规则**。

### 少弹窗还是多把关：审批力度

设置项 `lingdongAgent.approvalPolicy`，只影响 Agent 模式：

| 档位 | 自动放行 | 仍要确认 |
|---|---|---|
| **均衡** `balanced`（默认） | 仓库内文件改动、构建/测试命令、git 提交 | 删除、`git push`、装依赖、访问网络 |
| **严格** `strict` | 只有只读操作 | 其余每一项 |
| **放行** `yolo` | 除硬性禁止项外全部 | 硬性禁止项（永不放行） |

**任何档位都不会放行**：越界访问仓库外的东西、读取凭据、提权、改注册表、格式化磁盘、系统级安装、强制推送。每笔文件改动始终有改前快照。

## 10. 教它你的规矩：规则 / 记忆 / 技能 / MCP

入口：对话框输入 `/rules`（别名 `/skills` `/mcp` `/memory`），或命令面板 → **Skills 与 MCP**。页面标题是「Agent 能力」，三个标签页：

### 10.1 规则与记忆

**规则文件**：点「新建项目 AGENTS.md」，把项目约定写进去，例如：

```markdown
# 项目约定
- 包管理器用 pnpm，不要用 npm install
- 注释和提交信息写中文
- 改完 TypeScript 一定跑 pnpm typecheck
- 不要改 legacy/ 目录下的任何文件
```

它会自动读取仓库根的 `AGENTS.md`，以及 `.grok/rules`、`.cursor/rules`、`.claude/rules` 下的 `*.md`（还有用户级同名目录）——**从 Cursor 或 Claude Code 迁过来的规则可以直接复用**。

**跨会话记忆**（默认关闭）：开启后它会把项目约定与结论写成本机 Markdown，新会话首轮自动带回相关内容。默认关是因为这会把对话里的结论长期留在磁盘上，需要你明确同意。

**语言服务（LSP）**：开启对应语言的服务后，它才有「跳转定义 / 找引用 / 看类型」这类代码智能；关着的话它只能靠文本搜索猜。改大型强类型项目建议打开。

### 10.2 Skills

把一套固定流程封成技能，对话里用 `/技能名` 触发。扫描三个位置：托管配置目录的 `skills`、本机 `~/.grok/skills`、当前仓库的 `.grok/skills`。仓库内的技能可以跟着代码一起提交，团队共用。

### 10.3 MCP 服务器

接外部工具：增删、启停、填凭据，**改动在下一轮对话生效**。

宿主自带的联网搜索（`lingdong_web`）由系统管理，不在这里、也不能删或覆盖。

## 11. 模型与服务商

入口：`/model`，或设置 → 模型设置。

| 你要做的事 | 怎么做 |
|---|---|
| 加密钥 | 展开服务商 → 填 API Key → 保存（进系统凭据库，页面不回显） |
| 换密钥 | 同上，重新保存即覆盖 |
| 删密钥 | 服务商详情里「删除密钥」 |
| 加模型 | 详情页下方填 Model ID → 添加（自动测连接） |
| 加 Poe | 服务商列表里一键添加，可同步模型目录、查积分余额 |
| 加自定义服务商 | 顶部「添加自定义服务商」，填 Base URL 与协议（`responses` / `chat_completions` / `messages` / `openai_compatible`） |
| 查余额 | 支持的服务商详情里「查看积分余额」（只在点击时查一次） |
| 看隐私状况 | 顶部「查看隐私状态」 |

**两条重要行为**：

- 模型要通过**能力探测**才能进 Agent 模式。探测不通过（不支持工具调用）会被限制在 Ask——如果发现它死活不肯改代码，先来这里看探测结果。
- 服务商找不到或缺密钥时**不会偷偷换成别的服务商**，会明确报错。你的数据不会在你不知道的情况下发给另一家。

## 14. 设置项：默认值与什么时候该改

`Ctrl+,` 打开设置，搜 `lingdongAgent`。

| 设置项 | 默认 | 什么时候改 |
|---|---|---|
| `windowShape` | `agent` | 想要标准 IDE 布局改 `ide` |
| `approvalPolicy` | `balanced` | 嫌弹窗多改 `yolo`（慎用）；要严格把关改 `strict` |
| `planStepGating` | 开 | 想让模型一次拿到整份计划自己跑就关掉 |
| `streamEditPreview` | `off` | 想边改边看对比改 `diff`；只想跟着看文件改 `reveal` |
| `verifyAfterEdit` | 开 | 极少需要关；关了它改完不自己复查 |
| `showReasoning` | 开 | 不想看推理原文就关（只留脱敏后的阶段文案） |
| `memory` | 关 | 想让它长期记住项目约定再开（会写本机磁盘） |
| `permissionTimeoutMs` | 300000（5 分钟） | 经常离开电脑可以调长；最小 10 秒 |
| `snapshotRetentionDays` | 30 天 | 磁盘紧张就调小 |
| `snapshotMaxTotalMb` | 512 MB | 同上。未处理与冲突的快照**不会**被自动清 |
| `model` | `deepseek-v4-flash` | 一般在模型设置页里改，不用手动动 |
| `sanitizeUpstreamResponses` | 开 | 出现奇怪的解析失败时可试着关掉排查 |
| `managedGrokHome` | 开 | 你要自己完全掌管引擎配置时才关 |
| `grokExecutable` / `grokHome` | 空 | 要指定自己的引擎路径时填；也可用命令「选择 Grok 可执行文件」 |

## 15. 出问题怎么查

### 先看日志

左下角 **日志**，或 `/logs` → 输出面板选「灵动 Agent」通道。日志带前缀，方便定位：`[shape]` 布局、`[workspace]` 切仓库、`[permission]` 权限、`[storage]` 存储、`[preview]` 编辑预览。

另外两个入口：命令面板 → **Agent 诊断（规则与能力）** 看规则有没有真的注入、**查看隐私状态** 看脱敏与托管配置。

### 常见现象对照表

| 现象 | 原因与处理 |
|---|---|
| 界面空着，什么也发不出去 | 没配密钥。`/model` 去配 |
| 它一直不肯改代码，只会说 | ① 当前是 Ask 或 Plan 模式，切 Agent；② 模型能力探测没通过，换一个支持工具调用的模型 |
| 一直转圈没反应 | 底部状态行看在等谁：等权限就去点卡片；等子 Agent 看右轨 Tasks；都不是就 `/reconnect` |
| 提示连接断开 | 会自动重连（约 1 秒 → 3 秒 → 8 秒）；不行就 `/reconnect`，仍不行看日志里 grok 进程是否退出 |
| 找不到引擎 / 提示 grok 不存在 | 命令面板 → **选择 Grok 可执行文件** 手动指定 |
| 它老是自己打开一堆文件标签 | `streamEditPreview` 设成 `off`（当前版本已是默认） |
| 拖文件进对话却被编辑器打开了 | 不要按 Shift。默认拖放进对话；按住 Shift 才是「让编辑器打开」 |
| 权限卡片弹得太频繁 | 用「本次会话允许」，或把 `approvalPolicy` 调成 `yolo`（清楚风险再改） |
| 改动被拒绝，说「不在仓库内」 | 目标文件不在当前活动仓库里。用仓库树的 `＋` 把那个文件夹加进来并切过去 |
| 撤销时提示冲突 | 该文件在它改完后又被动过，为了不覆盖你的手改而跳过。手动处理或先看 Diff |
| 上下文老是满 | `/context` 看占用明细，`/compact` 压缩，或 `/clear-context` 清掉待发送项 |
| 联网搜索/抓取失败 | 先在浏览器里试同一个地址：多数是本机网络或目标站点不可达，不是产品故障 |
| 会话不见了 | 会话按仓库分开存。确认当前活动仓库是不是切走了，切回去就在 |
| 装完打不开 / 被拦 | 安装包未做代码签名，SmartScreen 可能拦截，选「仍要运行」 |

### 存放位置（需要备份或清理时）

安装目录：`%LOCALAPPDATA%\Programs\Lingdong Code`

用户数据在扩展的 globalStorage 下：

```
agent-sessions/<仓库哈希>/     会话、转写、轮次、计划
agent-permissions/<仓库哈希>.json  记住的权限规则
agent-providers/providers.json     服务商配置（不含密钥明文）
agent-snapshots/<仓库哈希>/    改前快照
grok-home/                     托管的引擎配置
```

API Key 不在上述任何文件里——它在 Windows 系统凭据库中，配置里只存一个引用 ID。
